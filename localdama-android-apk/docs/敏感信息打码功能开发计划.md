## 敏感信息打码功能 — 实现步骤

### 背景

在现有身份证打码流程基础上，新增"敏感信息打码"功能：用户从图库选取图片，通过 OCR 检测+识别文本，再用正则表达式匹配手机号、身份证号等敏感信息，自动对匹配区域打码（复用现有结果页面）。

核心差异在于**正则表达式匹配**，其余逻辑（图库选取、OCR 检测、结果展示、打码渲染）尽量复用已有模块。

---

### 文件规划（低耦合）

| 文件 | 职责 |
|------|------|
| `engine/OcrRecognizer.kt` | 通用文本识别引擎，基于 `rec_v5.onnx` |
| `feature/sensitive/SensitivePattern.kt` | 正则表达式规则定义 |
| `feature/sensitive/SensitiveDetector.kt` | 检测 → 识别 → 正则匹配 → 过滤管道 |
| `feature/sensitive/SensitiveInfoScreen.kt` | UI：图库选取 → 检测 → 跳转结果页 |

---

### Step 1：创建 `engine/OcrRecognizer.kt`

基于 PP-OCRv5 升级指南的参考实现，封装文本识别引擎。

- 加载 `rec_v5.onnx` 模型（ONNX Runtime）
- 模型输入：`[1, 3, 48, 320]`，归一化 `mean=0.5, std=0.5`
- 模型输出：`[1, seq_len, 18385]`
- CTC greedy decoding（blank=0，跳过重复字符）
- 字典文件：`ppocrv5_dict.txt`（注意无下划线，与指南中 `ppocr_v5_dict.txt` 不同）
- 字典首行需为空行（对应 CTC blank index 0），末尾需有空格
- 对外暴露接口：`fun recognize(context: Context, cropBitmap: Bitmap): String`

### Step 2：创建 `feature/sensitive/SensitivePattern.kt`

定义内置正则表达式规则，与业务逻辑隔离。

- 手机号：`1[3-9]\d{9}`
- 身份证号：`[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]`
- 银行卡号：`\d{16,19}`
- 电子邮箱：`[\w.-]+@[\w.-]+\.\w+`
- 车牌号：`[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤川青藏琼宁][A-Z][A-HJ-NP-Z0-9]{4,5}[A-HJ-NP-Z0-9挂学警港澳]`
- 提供 `SensitivePattern` data class（name, regex, enabled）
- 提供默认列表 `defaultPatterns()`

### Step 3：创建 `feature/sensitive/SensitiveDetector.kt`

串联完整检测管道：检测 → 识别 → 正则匹配 → 过滤。

1. 调用现有 `DetectionEngine` 的文本检测（`det_v5.onnx`），获取所有文本区域 bounding box
2. 逐区域裁剪，调用 `OcrRecognizer.recognize()` 获取文本
3. 遍历 `SensitivePattern` 列表，正则匹配识别结果
4. 仅保留匹配到敏感信息的区域，返回 `List<Rect>`（与现有 `detectedRegions` 格式一致）
5. 对外暴露接口：`fun detectSensitiveInfo(context: Context, bitmap: Bitmap): List<Rect>`

### Step 4：重写 `feature/sensitive/SensitiveInfoScreen.kt`

UI 界面，当前为占位页面（"功能开发中"），需要改为完整功能页面。

- 仅支持图库选取（不需要拍照），使用 `ActivityResultContracts.PickVisualMedia`
- 选取后调用 `SensitiveDetector.detectSensitiveInfo()`
- 识别过程中显示加载动画（复用 OCR 测试页风格：`CircularProgressIndicator` + "识别中..."）
- 识别完成后跳转 `ResultScreen`（复用现有结果页，传入检测到的区域）
- 如果未检测到敏感信息，弹窗提示（复用身份证识别失败的 `AlertDialog` 样式）

### Step 5：导航图接入

修改 `navigation/DamaNavGraph.kt`：

- 将 `SensitiveInfoScreen` 占位路由替换为完整功能页面
- 传递 `onDetectionDone` 回调，跳转到 `ResultScreen`
- `ResultScreen` 传入检测区域、初始马赛克风格等参数

### Step 6：验证

- 编译通过，无报错
- 图库选取图片正常
- OCR 检测+识别管道运行正常
- 正则匹配结果正确（手机号、身份证号等）
- 结果页打码渲染正常
- 未匹配到时弹窗提示正常

### 备注

- `rec_v5.onnx` 和 `ppocrv5_dict.txt` 已确认存在于 assets 目录
- 字典文件名为 `ppocrv5_dict.txt`（无下划线），与升级指南中的 `ppocr_v5_dict.txt` 不同，需注意
- `SensitiveDetector` 依赖现有 `DetectionEngine` 的文本检测能力，不重复实现检测逻辑
- `SensitiveInfoScreen` 复用 `ResultScreen` 进行打码结果展示，不重复实现打码渲染
